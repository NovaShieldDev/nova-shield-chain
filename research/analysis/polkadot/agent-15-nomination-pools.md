## 2. Pool State Machine

### Pool State Enum (lib.rs:701-711)

```
Open → Blocked → Destroying (tek yön, geri dönüş yok)
Open → Destroying
Blocked → Destroying
```

```rust
pub enum PoolState {
    Open,       // Herkes katılabilir, normal çalışır
    Blocked,    // Kimse katılamaz, root/bouncer kick edebilir
    Destroying, // Kimse katılamaz, tüm üyeler permissionless çıkarılabilir
                // Bir kez Destroying'e girince bir daha çıkılamaz
}
```

**State geçiş kuralları** (lib.rs:2679-2694):
- Herhangi biri → `Destroying`: pool'un `ok_to_be_open()` testi başarısız olursa permissionless olarak ayarlanabilir (lib.rs:2685)
- `root` veya `bouncer` → istediği state (Destroying olmadıkça)
- `Destroying` → değiştirilemez (`CanNotChangeState`)

**Destroying tetikleyicileri** (lib.rs:1183-1208, `ok_to_be_open`):
- `bonded_balance == 0` → `OverflowRisk`
- `points / bonded_balance >= MaxPointsToBalance` → `OverflowRisk` (ağır slash durumu)

### Pool Lifecycle — Tam Akış

```
create() → [Open]
    ↓
join() / bond_extra()
    ↓
nominate() → aktif nominator
    ↓
claim_payout() → ödül alımı
    ↓
unbond() → [SubPools/with_era] (bonding_duration era bekle)
    ↓
withdraw_unbonded() → üye çıkışı
    ↓
[son üye + depositor çıkınca] → dissolve_pool()
```

## 7. Ödül Sistemi

### 7.1 Reward Counter Mekanizması

Reward pool, **tek bir reward counter (rc)** takip eder. Bu counter her zaman artar ve üyelerin `last_recorded_reward_counter` değerine kıyasla hesaplanan fark, üyenin payını verir.

`T::RewardCounter` = `FixedU128` (mock'ta: lib.rs mock:34)

### 7.2 `current_reward_counter()` Formülü (lib.rs:1450-1512)

```rust
fn current_reward_counter(
    &self, id, bonded_points, commission
) -> Result<(T::RewardCounter, BalanceOf<T>), Error<T>> {

    let balance = Self::current_balance(id);
    // Mevcut ödeme bakiyesi:
    // = reward hesabı bakiyesi + toplam ödenen + toplam ödenen komisyon - son kayıt
    let current_payout_balance = balance
        .saturating_add(self.total_rewards_claimed)
        .saturating_add(self.total_commission_claimed)
        .saturating_sub(self.last_recorded_total_payouts);

    // Komisyon kesimi:
    let new_pending_commission = commission * current_payout_balance;
    let new_pending_rewards = current_payout_balance.saturating_sub(new_pending_commission);

    // Reward counter artışı = yeni_ödüller / toplam_points
    let current_reward_counter =
        T::RewardCounter::checked_from_rational(new_pending_rewards, bonded_points)
            .and_then(|r| self.last_recorded_reward_counter.checked_add(&r))
            .ok_or(Error::<T>::OverflowRisk)?;

    Ok((current_reward_counter, new_pending_commission))
}
```

### 7.3 `update_records()` (lib.rs:1408-1446)

Şu durumlarda **mutlaka çağrılmalı**:
1. Pool points değiştiğinde (join, bond_extra, unbond)
2. Komisyon oranı değiştiğinde

```rust
fn update_records(&mut self, id, bonded_points, commission) {
    let (current_reward_counter, new_pending_commission) =
        self.current_reward_counter(id, bonded_points, commission)?;

    self.last_recorded_reward_counter = current_reward_counter;
    self.total_commission_pending += new_pending_commission;

    // last_recorded_total_payouts sadece artabilir (azalamaz)
    let new_total_payouts = balance + total_rewards_claimed + total_commission_claimed;
    self.last_recorded_total_payouts = max(self.last_recorded_total_payouts, new_total_payouts);
}
```

## 9. Slash Mekanizması

### 9.1 TransferStake Slash (lib.rs:4335-4384, `on_slash`)

Pool account staking'de slash alırsa `sp_staking::OnStakingUpdate::on_slash` çağrılır:

```rust
fn on_slash(
    pool_account: &T::AccountId,
    slashed_bonded: BalanceOf<T>,           // Slash sonrası kalan bonded bakiye
    slashed_unlocking: &BTreeMap<EraIndex, BalanceOf<T>>,  // Era → yeni bakiye
    total_slashed: BalanceOf<T>,
) {
    // TotalValueLocked azaltılır
    TotalValueLocked::<T>::mutate(|tvl| tvl.defensive_saturating_reduce(total_slashed));

    // SubPools'ta her era'nın balance'ı güncellenir (points DEĞİŞMEZ!)
    slashed_unlocking.iter().for_each(|(era, slashed_balance)| {
        if let Some(pool) = sub_pools.with_era.get_mut(era) {
            pool.balance = *slashed_balance;  // Balance güncellenir, points ayni kalır
        }
    });

    // Event: PoolSlashed + UnbondingPoolSlashed
}
```

**KRITIK TASARIM KARARI**: Slash sonrası **points değişmez**, sadece **balance düşer**. Bu, her üyenin points:balance oranını otomatik olarak değiştirir (herkese eşit yansır).

```rust
fn member_pending_slash(member_account, pool_member) {
    // Pool'un bekleyen slash'ı yoksa üyenin de yoktur
    if T::StakeAdapter::pending_slash(pool_account).is_zero() {
        return Ok(Zero::zero());
    }

    // Gerçek tutulan bakiye (delegation hesabındaki)
    let actual_balance = T::StakeAdapter::member_delegation_balance(member);

    // Pool'da beklenen bakiye
    let expected_balance = pool_member.total_balance();

    // Fark = uygulanmamış slash
    Ok(actual_balance.saturating_sub(expected_balance))
}
```

**`withdraw_unbonded`'da otomatik slash** (lib.rs:2417-2432): Withdraw sırasında bekleyen slash varsa önce `do_apply_slash` çağrılır.

## 10. Komisyon Sistemi

### 10.1 Komisyon Hesaplama

Komisyon, `new_pending_commission = commission_rate * current_payout_balance` formülüyle hesaplanır.

`current_payout_balance`:
```
= reward_account_balance
+ total_rewards_claimed
+ total_commission_claimed
- last_recorded_total_payouts
```

Yani: **mevcut dönemde gelen yeni ödüller** × komisyon oranı.

### 10.2 Komisyon Kısıtlamaları (lib.rs:802-959)

```rust
// Throttle kontrolü (lib.rs:802-840):
fn throttling(&self, to: &Perbill) -> bool {
    // Azaltma → throttle yok
    if to <= current_commission { return false; }
    // max_increase aşılıyor mu?
    if (to - current) > change_rate.max_increase { return true; }
    // min_delay geçti mi?
    let blocks_surpassed = current_block - throttle_from;
    blocks_surpassed < change_rate.min_delay
}
```

**Kısıtlamalar**:
- `max`: bir kez ayarlandıktan sonra sadece azaltılabilir (lib.rs:895-896)
- `change_rate`: bir kez ayarlandıktan sonra sadece daha kısıtlayıcı yapılabilir (lib.rs:954-958)
- Sıfır komisyon → `None` olarak saklanır (lib.rs:870-872)
- `GlobalMaxCommission` her zaman uygulanır (lib.rs:845-850)

### 10.3 `claim_commission()` (lib.rs:3709-3751)

1. İzin kontrolü (`can_claim_commission` — root veya izin verilmiş hesap)
2. `reward_pool.update_records(...)` — bekleyen komisyon güncelle
3. `commission = reward_pool.total_commission_pending`
4. `Currency::transfer(reward_account → payee, commission, Preserve)`
5. `total_commission_claimed += commission`
6. `total_commission_pending = 0`

### 10.4 Komisyon Claim İzinleri (lib.rs:747-750)

```rust
pub enum CommissionClaimPermission<AccountId> {
    Permissionless,       // Herkes çekebilir
    Account(AccountId),   // Sadece bu hesap veya root
}
```

### 10.5 Pool Yok Edildiğinde (lib.rs:3395-3405)

Kalan reward bakiyesi (ödenmemiş komisyon dahil) depositor'a transfer edilir.

## Kritik Bulgular Özeti

1. **Points:Balance 1:1 başlar, slash ile değişir** (lib.rs:423, 3482-3498): Slash sonrası points sayısı değişmez, balance düşer. Pool'a katılırken dönüşüm bu orana göre yapılır.

2. **U256 aritmetiği zorunlu** (lib.rs:3480-3481): `balance_to_point` ve `point_to_balance` fonksiyonları u128 taşmasını önlemek için U256 kullanır. Her runtime implementasyonu `BalanceToU256` ve `U256ToBalance` sağlamalı.

3. **Reward counter'ı points değişmeden önce güncelle** (lib.rs:2142-2146, 2278-2288): `join`, `bond_extra`, `unbond` extrinsic'lerinde `update_records()` **mutlaka** yeni points hesabından önce çağrılmalı. Aksi halde ödül hesabı yanlış olur.

4. **depositor_min_bond = max(MinNominatorBond, MinCreateBond, MinJoinBond, ED)** (lib.rs:3288-3293): Depositor hiçbir zaman bu miktarın altına inemez.

5. **MaxUnbondingPools > bonding_duration ZORUNLU** (lib.rs:3271-3276): Integrity test bunu zorlar. Aksi takdirde bir slash, ilgili unbonding pool'u merge'den önce bulmayabilir.

6. **TransferStake deprecated** (adapter.rs:255): `#[deprecated = "consider migrating to DelegateStake"]`. Yeni runtime'lar DelegateStake kullanmalı.

7. **Slash TransferStake'de greedy (anında), DelegateStake'de lazy (ertelenmiş)** (adapter.rs:332-344, 443-453): TransferStake'de `pending_slash` her zaman sıfır döner, DelegateStake'de `apply_slash` permissionless çağrılmalı.

8. **Destroying state'ten geri dönüş yok** (lib.rs:2679): Bir kez Destroying'e girilince durum değiştirilemez.

9. **Pool yok edilirken kalan reward bakiyesi depositor'a gider** (lib.rs:3395-3405): Ödenmemiş komisyon dahil tüm reward bakiyesi depositor'a transfer edilir.

10. **Pool silindiğinde reward account ED freeze kaldırılır** (lib.rs:3371): `unfreeze_pool_deposit` çağrılır.

11. **Reward account her zaman ED ile protect edilir** (lib.rs:3616, 3608-3613): Pool oluşturulurken depositor reward hesabına ED transfer eder ve `FreezeReason::PoolMinBalance` ile dondurulur.

12. **Komisyon oranı yalnızca `update_records` anında uygulanır** (lib.rs:1469): Komisyon, komisyon güncellemesinden sonra gelen ödüllere uygulanır. Bu, kötü niyetli komisyon artışını önler.

13. **SubPools merge mantığı** (lib.rs:1608-1629): `effective_post_unbonding_window = MaxUnbondingPools - bonding_duration`; bu pencereden daha eski era'lar `no_era` pool'una merge olur. No_era pool'unda points:balance oranı ortalanır (slashed oranlar da dahil).

14. **Genesis defaults** (lib.rs:1843-1853): max_pools=16, max_members_per_pool=32, max_members=512 — üretim için genellikle çok düşük.

15. **`ClaimPermission` default `PermissionlessWithdraw`** (lib.rs:487-490): Üye ayarlamasa bile başkası onun adına payout çekebilir. Bu, compound botu senaryolarını kolaylaştırır ancak dikkat edilmeli.

## Nova Shield Chain Notları

### 1. DelegateStake Stratejisini Tercih Et

TransferStake deprecated ve güvenlik açıkları mevcut (slash anında değil, pool hesabında tutulur). Nova Shield Chain yeni bir zincir olduğu için **DelegateStake** stratejisiyle başlamalı. Bu, kullanıcıların stake'lerini kendi hesaplarında tutmasını sağlar.

### 2. MaxUnbondingPools ve Bonding Duration İlişkisi

Nova Shield Chain'in bonding_duration değerini belirledikten sonra:
`MaxUnbondingPools = bonding_duration + güvenlik_marjı` (en az +2 önerilir)

Örnek: bonding_duration=28 era → MaxUnbondingPools=32 minimum.

### 3. Reward Counter Tipi

`RewardCounter = FixedU128` güvenli bir seçim. Token miktarı DOT benzeri (1e10 granülerlik) ise hesap:
- Max güvenli reward accumulation: u128 sınırından çok önce (onlarca yıl)
- `smallest_claimable_reward ≈ 10^-8 token`

### 4. Genesis Parametreleri

Üretim için daha yüksek değerler:
```rust
max_pools: None,         // veya büyük sayı
max_members_per_pool: None,  // veya büyük sayı
max_members: None,
global_max_commission: Some(Perbill::from_percent(20)),  // %20 max
```

### 5. ClaimPermission Default'u Değiştir

Default `PermissionlessWithdraw` yerine `Permissioned` tercih edilebilir. Kullanıcılar açıkça izin vermeden reward compound edilemez.

### 6. Komisyon Throttle Tasarımı

Kullanıcıları komisyon manipülasyonundan korumak için:
- `GlobalMaxCommission = Some(Perbill::from_percent(20))`
- Pool'lara `change_rate.max_increase = 5%` ve `min_delay = 7200 blocks (~24h)` önerilebilir

### 7. Filter Trait — Staking Çakışması

`type Filter: Contains<AccountId>` ile mevcut staker'ların pool'a girmesi engellenebilir. Nova Shield Chain için bu kritik: bir hesap ya doğrudan staking yapar ya da pool üyesi olur, ikisi birden değil.

### 8. U256 Dönüşüm Implementasyonu

`BalanceToU256` ve `U256ToBalance` converter'larını dikkatli implemente et. Infallible olmalı (truncation kabul edilebilir).

### 9. Reward Hesabı ED Yönetimi

ED değişirse pool'ların `adjust_pool_deposit` çağırması gerekir. Nova Shield Chain'de ED değişimlerinde otomatik migration planlanmalı.

### 10. Pool Account Derivation

`PalletId::into_sub_account_truncating` ile türetilmiş hesaplar keyless. PalletId seçimi kritik — çakışma olmamalı. Örnek: `b"py/nopls"` (8 byte).

### 11. Weight Kalibrasyonu

`join` operasyonu ~202ms — bu yüksek. Polkadot için optimize edilmiş değerler, Nova Shield Chain donanımına göre yeniden benchmark edilmeli. Özellikle `withdraw_unbonded_kill` (25 read, 21 write) en ağır operasyon.

### 12. on_slash Hook Entegrasyonu

`sp_staking::OnStakingUpdate<AccountId, Balance>` trait implementasyonu pallet-staking ile bağlantı için zorunlu. `ReversePoolIdLookup` storage'ı bu hook için kritik — slash mesajını pool'a yönlendirmek için kullanılır.
